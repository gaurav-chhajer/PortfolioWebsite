Fails safely, in practice

I'm Gaurav, a software engineer with a B.Tech in Computer Science (AI & ML) from UPES. I write Kotlin, Java and Python, and I like work where the edge cases are the job: OCR output that has to become clean transaction data, and LLM scores that have to be checked before anyone sees them.

Four rules, each from real work. Scroll to follow one record through them.

  1. A failed fetch never closes live jobs.

    StudentConnect keeps complete snapshots separate from partial feeds, so one broken career page can't empty the catalog.

  2. Raw ML output becomes structured data first.

    At OneBanc I built multi-stage pipelines on Kotlin Coroutines and Flow that turn OCR results into structured data before they reach transaction workflows.

  3. Invalid model output never reaches a user.

    Every LLM fit score is checked for its total, category and evidence reference against numbered source lines before it is stored.

  4. An uncertain send is never retried automatically.

    If an SMTP result is unclear, StudentConnect does not resend. A flaky mail server can't turn into duplicate digests.

AI automation, full-stack

StudentConnect

A Python system that pulls jobs from company career sites, scores them against a profile with an LLM, and emails a daily digest.

  • Separates complete snapshots from partial feeds, so a failed fetch never closes live jobs.
  • Validates every LLM score against a 100-point rubric and numbered source lines, and falls back from Groq to Gemini on HTTP 429 with the same checks.
  • Durable matching tasks, stale-score marking and process locks keep results correct across restarts and profile edits.
  • Scheduled runs use GitHub Actions and an authenticated worker API. Uncertain SMTP sends are never auto-retried.

Scheduled automation and LLM scoring that can run unattended without sending bad data or duplicate emails.
