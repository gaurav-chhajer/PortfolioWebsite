Fails safely, in practice

I'm Gaurav, a software engineer with a B.Tech in Computer Science (AI & ML) from UPES. I write Kotlin, Java and Python, and I like work where the edge cases are the job: OCR output that has to become clean transaction data, and job matches that have to stay correct when a data source fails halfway.

Four rules, each from real work. Scroll to follow one record through them.

  1. A failed fetch never closes live jobs.

    StudentConnect keeps complete snapshots separate from partial feeds, so one broken career page can't empty the catalog.

  2. Raw ML output becomes structured data first.

    At OneBanc I built multi-stage pipelines on Kotlin Coroutines and Flow that turn OCR results into structured data before they reach transaction workflows.

  3. A sync never overwrites hosted data.

    StudentConnect's local worker sends job observations to the hosted site additively. Scores are computed from hosted profiles, and every write is validated against current company and user state.

  4. An email send is reconciled, not guessed.

    Email digests keep their own history with separate failure and reconciliation safeguards. The dashboard and the sync process never send mail.

AI automation, full-stack

StudentConnect

A job-discovery and resume-matching platform. It collects openings from company career sites, ranks them against your resume with a local ML model, and tracks applications in an authenticated web app.

  • Pulls from 50+ company career sources through source-specific adapters with validation, pagination and deduplication. A failed read keeps the previously saved jobs.
  • Ranks openings with a local Sentence Transformers model (all-MiniLM-L6-v2) plus skill overlap, and keeps relevance ranking separate from verified fit scores.
  • An authenticated sync moves jobs from a local worker to the hosted dashboard without overwriting it. The first run transferred 20,685 job observations and 81 new scores were accepted.
  • Worker API keys are separate, fetching is allowlisted and size-bounded, and GitHub Actions runs the offline tests before deploying to PythonAnywhere.

Scheduled data collection, ML ranking and a synced web dashboard that keep working when a source goes down.
